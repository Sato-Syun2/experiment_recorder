## 今回のデータでの選び方

**約15 m側からの骨格形状を優先するなら、ACCURATE / GEN_2を第一候補とする。** MEDIUM / GEN_2も遠方でSDK出力が続き、処理は軽いが、002では足が床下へ入る傾向が大きい。003の約9 m以内の接近で処理負荷を抑える用途ではMEDIUM / GEN_2も候補になる。

ただし、ACCURATE / GEN_2でも初期にかかとが推定床面より約−0.38 mになる値が残る。**15 mからの全関節を正確に測定できるという承認ではない。** 身体寸法・関節位置の独立真値がなく、正確な歩幅・関節角・絶対位置の「最良モデル」はこの比較だけでは確定できない。録画002・003の1人の例に基づく用途別の候補選定。

MEDIUM/GEN_2の最大骨盤Xは約15.05 m、ACCURATE/GEN_2は約14.62 mだが、「15に近い方が正確」とは判定しない。廊下方向原点はセンサーの投影位置で、測量した廊下端との一致・センサー間の並進・時計差は未確定。真の身体中心位置の時系列もない。

## 過去結果との差

今回のSDK 5.5.1上の **ACCURATE/GEN_1と、以前の002のSDK出力は、411人物行の全3D関節が数値上完全一致**した。SDK更新だけでこの録画の旧モデルの骨格が改善した結果ではない。過去の実SDKパッチ版の記録がないという制限は引き続きある。

ACCURATE/GEN_1→GEN_2では、同じ414フレームに対して両脚の信頼度条件を満たす件数が307→388、骨長比の偏差p90が34.9%→16.1%、床下の足を含む件数が57→24となった。SDK内部で世代に伴う処理が変わるため、ニューラル構造以外の内部要因まで個別に分解した原因実験ではない。

## 003：ポール下の接近

接近から新規にSDKを起動した同じ249フレームでは:

|設定|SDK OK|両脚条件通過|SDK処理ms中央値|
|---|---:|---:|---:|
|MEDIUM / GEN_2|245（98.4%）|191（76.7%）|55.6|
|ACCURATE / GEN_2|245（98.4%）|191（76.7%）|72.1|
|MEDIUM / GEN_1|242（97.2%）|158（63.5%）|56.2|
|ACCURATE / GEN_1|243（97.6%）|173（69.5%）|69.7|
|FAST / GEN_1|228（91.6%）|123（49.4%）|42.7|

GEN_2の2モデルはこの区間で同じSDK出力・両脚条件の件数。MEDIUMはSDK処理時間の中央値が約23%短い。相対骨長変動の指標もMEDIUMに利点があるが、同じ人物の真の身体寸法と照合した精度判定ではない。

全区間を継続追跡した場合は、MEDIUM/GEN_2でIDが0→2に切り替わり、SDK OKのIDが同時に2個になるフレームが3件あった。ACCURATE/GEN_2はID 0のまま。MEDIUMの切替は折返し付近で、ポール通過が原因とは断定しない。

自動比較ページの「主要ID」は件数最大の1 IDだけから骨格指標を計算するため、MEDIUM/GEN_2の全区間では往路のID 0を除外してしまう。**その列を全歩行の両脚成績と解釈しない。** 新規確認では画像で人が見える広めの共通窓8.0〜20.5秒・373フレームについて、全SDK OK IDの和集合で時刻を1回だけ数えた。

|---|---:|---:|---:|
|MEDIUM / GEN_2|373|372|3|
|ACCURATE / GEN_2|373|373|0|
|MEDIUM / GEN_1|373|250|0|
|ACCURATE / GEN_1|373|306|0|

この広めの窓は精密な遮蔽・関節可視性ラベルではない。画像確認した代表場面ではポール・チェーンの脇を歩く人物に骨格が対応しており、ZEDの人物経路確認は可能。ただし脚がポールと重なる場面の関節位置の正確さは保証できない。003のZED床校正はまだ独立確認しておらず、002の変換を流用した高さの正常判定はしていない。

初期の003の画面左下には近接した人物の頭の一部が写っており、ACCURATE/GEN_2はその段階から骨格を出す。全区間の高いSDK OK率だけから「空の場面でポールを人と誤検出した」、または「常に全身が正しく見えた」とは判断しない。

LiDARについては、先の003解析で確定人物検出が0/273だった結果を変更していない。ZEDの骨格が出ることと、LiDARの確定人物追跡が成功することは別。002と003は歩行距離・経路・遮蔽物の条件が異なり、ポールの有無だけの因果比較ではない。
