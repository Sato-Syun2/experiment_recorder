# 2人の廊下歩行・追越し動作を測定できるかのレビュー

作成日: 2026-10-22。目的: 追い越される人が、実験条件によって横へ譲る、減速する、姿勢を変える等の特徴的な動作を示すかを判別する。

**現時点では、2人の追越しを連続自動追跡し、条件による動作差を十分な精度で測れるとは判定できない。1人の接近経路を確認できた実績はあるが、2人の遮蔽・ID維持・動作量の誤差が未評価である。大きな側寄せや停止を映像で人手判定する研究は進められる可能性がある。数cmの変位、微小な減速、関節角・歩幅を自動で確定する用途は現状では採用しない。**

これは機器の原理上の不可能性を示す判定ではなく、現在の実証範囲と処理上の制約に対する判定である。今回、新たなSDK解析、bag再処理、テスト、ZED・Livox・ROS 2・RVizの操作は行っていない。既存のREADME、レポート、保存指標、設定、コード、代表画像を読み取った。録画原本・メタデータ・運用設定・校正・既存解析結果は変更していない。

## 1. 現在の証拠から言えること

最新の接近のみの再解析を、旧来の往復連続処理と区別して評価する。

1人歩行で得た局所残差中央値2.1 cmは短時間の滑らかさである。壁・ポールの当てはめ残差、センサー間相関r=0.991も、人体中心や回避量の真値誤差へ置き換えない。独立した位置・動作真値がないため、「±何cm」「判別正解率何%」という現状の保証値は出せない。

10/21録画003のrecording.jsonには計画由来の追越し条件があるが、既存の入力確認・映像評価では1人往復である。今回確認した資料に、実2人の追越しを独立ラベルで評価した結果は見当たらない。メタデータの条件名だけで2人実験の実施・成功を認定しない。

## 2. 目的に合わせた測定項目

全身骨格の完成を待つより、まず追い越される人の平面運動を主要評価にする。各試行の条件・役割は必ずrun_order.jsonから読み、実映像で人物対応と実施内容を別途確認する。

| 評価項目 | 定義の方針 | 現状の採否 |
| --- | --- | --- |
| 横への譲り | 接近前の経路・横揺れを基準にした符号付き横変位、最大側寄せ、元の経路への復帰 | 最優先。2人のIDと身体代表点が保てた区間で検証後に採用 |
| 減速・停止 | 接近前の本人の歩行速度からの低下量・低下率、停止時間 | 優先。単なる「遅い」教示との混同を防ぐ。生位置の差分速度をそのまま採用しない |
| 動作開始の時機 | 側寄せ・減速の持続的変化が始まる時刻、追越しイベントからの時間差 | 同期とフィルタによる時刻誤差を評価してから採用 |
| 人物間距離 | 共通の身体代表点同士の前後差・横間隔・最接近 | 2人同時実観測を要求。クラスタ中心間距離を身体表面間の余裕距離と呼ばない |
| 肩・体幹の回旋、振り返り | 映像での行動注釈を先行し、必要なら検証済み関節から角度化 | 探索項目。LiDAR中心の軌跡だけでは識別できない |
| 歩幅、足先、関節角 | 独立した関節・足接地参照と比較 | 現状は主要評価から外す |

追越し基準時刻は、同じ身体基準点について前後位置が入れ替わる時刻等として事前に定める。歩行方向を正とする軸を定義し、接近方向の廊下X減少を後退と誤認しない。欠測をまたいだ交差時刻は不確かさを伴う区間として扱い、補間した一点を確定時刻にしない。

左右の比較は廊下Yの生の符号だけで行わず、歩行者から見た追越し側・反対側に統一する。基準横位置は「最初に取れた1観測」より接近前の一定区間の中央値・基準経路を使う。自然な歩行時の横揺れや元の斜行を差し引ける定義にする。

## 3. コードから見た主な制約と修正方針

### 3.1 近接2人の点群を分ける処理が不足している

`scripts/track_people.py`の`detect_clusters`は点群の連結成分を1候補とし、その中央値を位置にする。設定は接続距離0.35 m、8 m以遠で距離ごとに拡大する。コードの距離尺度で15 mなら約0.434 mになる。これは点同士の接続条件であり、人体中心がその距離なら必ず混ざるという境界ではない。複数の点を経由して連結する場合もある。

最大幅・奥行きが各2 mのため、近接2人の連結成分が1人候補として残る可能性がある。現行の等速予測とHungarian法は既に導入済みだが、1対1割当てなので、1つになった観測から2人の実位置を回復できない。合体中央値をどちらかのIDへ割り当てると、見かけの側寄せ・加速やID誤対応を生む恐れがある。

**修正方針:** 2つの予測軌跡が1つの点群へ入る場合の合体・曖昧フラグを追加する。画像の人物別マスク、胴体付近の点、過去の形状・運動を分割の手掛かりとして比較する。分離を支持する実観測が足りなければ欠測・遮蔽とし、2人分の確定位置を生成しない。接続距離だけを小さくすると遠方の1人を分裂させるため、単純な閾値縮小では解決しない。

### 3.2 初期確定・再捕捉条件が遅い歩行や欠測に厳しい

`_update_matched_track`は、未確定トラックの確定時に15観測の連続した運動窓、最大移動0.8 m、移動整合性0.55、点数条件等を要求する。約10 Hzでは15連続観測を得るだけで最短約1.4秒かかり、1回欠測すると最近位置窓がリセットされる。運動証拠の加算には1更新あたり5 cm以上の変位も使うため、低速の初期捕捉では満たしにくい。

この構造は録画003の未確定期間と整合する。確定済みの同一トラックが停止しただけで直ちに未確定へ戻る処理ではないが、最初の検出やID消失後の再捕捉が問題になる。「遅い」「避ける」条件だけ有効データが少なくなると、条件差の評価も偏る。

**修正方針:** 人物としての存在証拠と、移動しているかの判定を分ける。短い欠測を許す時間窓内の観測支持、画像人物証拠、形状・点数から確定を判断し、再捕捉にも同じ人物の履歴を利用する。確定前の生観測は別列として保持する。閾値だけ緩めて成功率を上げず、空の廊下、静止人物、遅い人物、壁際の誤検出を同じ検証集合で比較する。

### 3.3 背景学習と実験開始の手順を合わせる

現設定の30フレームは約3秒。`PersistentClusterModel`は学習中の候補を出力せず、初期に滞在した人物を背景候補へ含め得る。`BackgroundModel`は点の占有を録画中も累積更新する構造である。

**修正方針:** 無人の廊下で背景を取得してから被験者を進入させ、その時刻を残す。処理側も空背景の学習終了・固定、または人物を保護する更新方法を明示する。壁・床モデルと廊下に沿う範囲制限で設備の候補を減らす。現行ROIのX±30 m、Y±15 mは広く、廊下に合う範囲制限が改善候補となる。ただしROIは水平化座標で適用されるため、廊下座標の幅をそのままY範囲へ代入しない。

### 3.4 SDK OK、融合、微分値を動作真値にしない

SDKの公式説明ではprediction timeout中も人物位置を予測し、SEARCHINGへの移行を遅らせる。現在の書き出しコードでは`prediction_timeout_s`と`skeleton_smoothing`を明示保存していない。98.9%はSDK OK出力率として扱い、全フレームの実画像検出成功率と呼ばない。

**修正方針:** SDK 5.4で利用可能な値を確認し、予測時間・骨格平滑化の実設定を明示保存する。測定用と再生用で観測・予測の扱いを分け、骨長・床との関係・関節confidence・映像一致を併記する。試行前に追跡状態を初期化する方式を優先候補とし、人物がいない状態から2人が入る本番条件で確認する。特徴的な動作の途中でリセットし、前後を黙って接続しない。新規起動での改善は深度・位置追跡も同時初期化した結果であり、body fittingだけが原因と断定しない。

`scripts/fuse_zed_lidar.py`は録画全体で固定したZED IDとLiDAR IDの1対1対応を使う。ID分裂や切替のある2人追越しには、時区間ごとの対応と曖昧性の記録が必要である。重み付き平均は同じ身体基準点・正しいID・同期・誤差モデルが揃ってから比較する。現時点では各センサーの値を別々に保持し、平均による見かけの滑らかさを精度向上と解釈しない。

`scripts/evaluate_tracking.py`の`pairs.csv`は同時刻の確定実検出間の値、`kinematics.csv`は無平滑の位置微分である。欠測を埋めない設計は適切だが、そのまま回避開始や減速量の確定値にはならない。生位置と品質を保持した上で時間窓の局所回帰等を比較し、変位振幅の減衰・開始時刻のずれを独立参照で確認する。約10 HzのLiDARを30 Hzへ補間しても計測情報は増えない。

## 4. 撮影・測定配置で効果が期待できる変更

**優先度が最も高いのは、追越し中の追い越される人を別方向から見られる映像の確保である。** 代表画像は廊下の長軸に沿う視点である。2人が同一直線上に並ぶと一方が隠れる幾何的な弱点があり、同じ方向から見るZEDとLiDARだけでは同時に情報が失われる可能性がある。実2人映像で頻度を確認する必要はあるが、閾値調整より優先して対処すべき設計上のリスクである。

1. 既存機器だけで進める場合、まず4〜8 m程度を主な評価区間の候補とし、足元と2人の全身が入るかを確認する。既存のセンサー間差が比較的小さかったことを根拠とする候補であり、合格済み区間ではない。12〜15 mは進入・接近状況の参考に留め、微小動作の主要解析へ無条件に含めない。
2. 追加できる場合は、追越しが生じる区間を斜め上方・側方から撮る固定カメラを、歩行や有効通路幅に影響しない位置へ置く。既存視点で隠れる追い越される人と足元を補う配置を優先する。一般のカメラも人手ID・動作注釈には役立つが、cm精度の位置真値には校正と身体基準点の定義が別途必要。
3. 全廊下を研究対象とするなら、都合のよい近距離区間だけを選ばず、観測範囲を追加して対応する。特定地点で避けるよう教示すると目的の動作自体が変わるため、測定のために反応地点を強制しない。区間限定の研究にする場合も条件間で区間と除外基準を統一する。
4. センサーを移動した場合は床・重力・廊下座標・外部校正を再取得する。現行の部分校正や10/21の候補を別設置へ流用しない。同期は両方式で観測できる動く共通事象を録画の前後に記録し、録画別のoffsetとdriftを確認する。開始時刻差や静的点群の近傍時刻だけを同期根拠にしない。

公式説明でもステレオ深度精度は距離とともに悪化する。最大深度設定や製品の最大測距を増やすだけでは、身体動作の測定精度は保証されない。撮影解像度や深度モデルの比較は、遮蔽・ID・独立評価を整えた後に実施する。

## 5. 本番採用を決める検証

以下は次回の検証方針であり、今回実施したテストではない。

- **実2人の評価データ:** run_order.jsonの幅・速度・左右・避ける/避けない・役割交代を覆う試行を確保する。1回の成功で保証せず、特に並走、前後に重なる場面、追越し直後、低速・停止、壁際を含める。予備確認と最終評価は被験者・録画単位で分ける。
- **人物ID・行動の参照:** 条件名を見ずに可能な範囲で映像を注釈し、誰が追い越される人か、存在・遮蔽区間、譲り・減速・停止・振り返りの有無と時刻を記録する。一部を複数注釈者で判定し、一致度と判定不能を残す。教示した「避ける」を実際に避けた正解ラベルとして流用しない。
- **位置参照:** 独立カメラ・測量した床基準等を使い、基準点を統一する。骨盤、可視表面の中央値、足接地点を区別する。床のホモグラフィを高さのある骨盤へそのまま適用しない。参照自体の空間・時間誤差も記録する。
- **評価指標:** 2人それぞれと2人同時の有効観測率、追越し前後のID Switch・ID分裂、欠測時間分布、横変位・速度変化・動作開始時刻の参照誤差を出す。対応できた観測だけのRMSEと、欠測・偽陽性を併記する。
- **条件ごとの欠測:** 幅・避ける/避けない・速度・左右別に評価可能試行率を出す。遮蔽区間を除外した後の結果だけでは回避動作全体を評価できない場合がある。除外率と理由を残し、条件差が測定失敗の差で生まれていないか確認する。

必要精度は「識別したい最小差」から決める。例として**横変位20 cm、速度低下0.2 m/s、開始時刻差0.3秒**を識別したいなら、動作量そのものの参照誤差95百分位を横変位5 cm以下、速度変化0.05 m/s以下、時刻0.1秒以下に抑えることを初期の設計目標にする。これらは今回の性能・一般規格ではなく、効果に対して余裕を持たせるための仮の目標である。数cmや数十msの差を目的にするなら、参照とセンサー構成をさらに見直す必要がある。

自動定量解析へ採用する試行は、主要イベント前後の人物対応が確認され、少なくとも動作開始・最大変位・速度低下を欠測がまたいでいないことを条件にする。IDの誤対応を残した試行は不採用とする一方、その試行を失敗率の分母から外さない。必要な観測率・許容欠測は、対象動作の長さと上記誤差目標に合わせて事前固定する。

## 6. 条件差を解釈する際の注意

run_order.jsonでは幅、回避教示、先行者速度、追越し方向、被験者の役割が指定されている。「条件ごとに特徴的か」は、同じ被験者の幅・速度・追越し方向を揃えた避ける/避けないの比較から始める。速度低下は本人の接近前速度を基準にする。

計画の単独歩行は通常速度・広い廊下の条件である。本人の通常歩行の横揺れや姿勢を知る参照には使えるが、狭い廊下・遅い歩行の全対照を代替しない。計画を追加変更する場合はExcelを更新してrun_order.jsonを再生成し、解析側へ条件表を重複実装しない。

条件の教示と実行動作を別々に記録する。「避ける」教示による側寄せの差は教示への反応・実行確認として解釈できるが、教示がない自然な回避の発生機序まで証明するものではない。統計単位はフレーム数ではなく試行・被験者を基本とし、同一被験者・グループ内の反復を扱う。自動分類を導入する場合も同じ録画の隣接フレームを学習側と評価側へ分けない。

## 7. 着手する順序

1. 主目的を「横への譲り・減速」として最小差、身体基準点、イベント時刻を定義する。
2. 既存機器の評価区間と、追い越される人の遮蔽を補う撮影配置を決め、録画別同期・設置校正を確認する。
3. 2人実録画に人物ID・存在・遮蔽・実行動作の注釈を付け、現行処理の失敗を可視化する。
4. LiDARの合体検出・分離不能の扱い、確定・再捕捉、背景学習を修正する。ZEDの初期化・予測・品質を明示し、センサー間のID対応を時区間で管理する。
5. 独立参照で動作量・時刻の誤差と条件別欠測を評価し、固定した基準を満たした指標・区間から本番集計に採用する。骨格角度・歩幅・自動分類はその後に拡張する。
