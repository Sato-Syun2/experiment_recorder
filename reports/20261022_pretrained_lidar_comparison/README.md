# 学習済みLiDAR人物検出と現行処理の実録画比較

2026-10-22。対象は **20261021_group002 / recording_003の1人往復、全318点群**。

**今回のPointPillarsへの置換で、現在の方法より自然な歩行経路が得られる改善は確認できなかった。近中距離の進行経路は両方式でおおむね一致するが、PointPillarsは遠方・折返しを欠測し、共通時刻での短時間の位置変動も現行候補より大きかった。ただし、現行の確定検出にも長い途切れがあり、両方式とも2人追越しの自動定量計測に合格した結果ではない。**

PointPillarsは人の3Dボックスを検出するモデルで、歩行動作分類器や骨格推定器ではない。本比較の「自然さ」は、映像上の人物に対応する経路、往復の連続性、観測位置の変動についての評価である。歩幅・足の接地・関節角が自然かどうかをこのモデルから判定したものではない。

## 実施内容と比較条件

1. 学習済み重みは **PointPillars / KITTI 3クラス / OpenPCDet由来**。実装はtorch-pointcloud 0.0.18。重みのrevisionは`caf39bd441409bdd2997d3099cc524ac451ff06d`、SHA-256は`053113b0c99a36191f9eccc8ceade76856ec7b39d4e374bc3737d501c67debb6`。追加学習はしていない。
2. GPUを利用できないため、専用環境`.venv_lidar_models/`のPyTorch 2.8.0 CPU版で実行した。既存の`.venv`は変更していない。CPUの柱状ボクセル化以外は公開パッケージのネットワーク・重み・ボックス復号を使う。ボクセル0.16×0.16×4 m、柱あたり32点、最大40000柱。公開設定に合わせ、score ≥0.1、クラスを分けない回転BEV NMS IoU 0.01を使用した。
3. 入力は元のXYZとLivox反射強度。録画003の既存の重力・床高で水平化し、主条件では仮想入力原点を床上1.73 mに置いた。これはモデル入力の座標変換で、機器の移設ではない。反射強度は0〜255に制限して255で割った。KITTIとLivoxの反射強度を物理校正したものではない。
4. 学習済みモデルには背景除去・現行の点群間引き・時間積算・画像による位置補正を使わず、モデルの規定入力範囲の全点を渡した。検出結果を見て位置や尺度を合わせていない。
5. 現行処理は**同じ全318点群と同じ録画003用の設置校正**で再実行した。校正JSONのパスだけ退避後の位置へ直した専用configを使用。再出力`baseline_tracks.csv`は既存評価の`tracks.csv`と**バイト単位で一致**した。
6. 廊下内の集計・表示ゲートは両方式共通で、廊下座標`0 < X < 20 m, |Y| < 1.2 m`。モデルのゲート外出力も`full/detections.csv`へ保存した。

録画原本・既存CSV・録画メタデータ・運用config・校正値は変更していない。ROSのbag読取りライブラリは使ったが、ZED・Livoxの実機、ROSノード、RVizは起動していない。録画データを外部サービスへ送っていない。

## 検出継続性

比較区間は従来評価と同じ**ZED経過2.0〜29.8秒の278 LiDARフレーム**。進入・退出や短い空の余白を含む広い区間であり、独立した人物存在ラベルに対する再現率ではない。

| 指標 | 現行の確定実検出 | 現行の映像対応済み候補を含む観測 | PointPillarsの人物出力 |
| --- | ---: | ---: | ---: |
| 区間内の出力フレーム | 93 / 278（33.5%） | 185 / 278（66.5%） | 157 / 278（56.5%） |
| 観測間の最大間隔 | 約11.399秒 | 約0.699秒 | 約8.500秒 |
| 出力位置の最大廊下X | 約14.84 m | 約15.02 m | 約12.23 m |

**3列は確定基準が異なる。56.5%対33.5%だけを比べて「検出率が23ポイント改善した」とは言わない。** 現行の候補を含めた185フレームも、人物の確定検出率には数えない。

PointPillarsの廊下内出力は往路80件、復路77件。往路はZED基準2.947〜11.747秒、復路は20.247〜28.147秒で、**11.747〜20.247秒に廊下内の人物出力がない**。約15 mで折り返す部分は再現できなかった。出力の最大位置は身体中心の真の到達距離ではなく、検出方式ごとの代表点の範囲である。

現行の確定状態だけでは復路の大半が欠ける一方、モデルは復路の中距離から人物を出力している。この点は、現行の移動量・連続観測による確定判定を見直す材料になる。ただし、モデル単独でも遠方の連続測定を回復したわけではない。

モデル出力へ現行と同じ0.55 mの等速予測ゲート、1.2秒の消失期限、0.65の速度更新係数で関連付けを行うと、廊下内は往路ID2、復路ID13になった。予測位置は観測として書き出していない。2連続出力を持つフレームは149/278（53.6%）だが、これは現行の移動確認を通った確定状態とは異なる。人物IDの真値評価もしていない。両方式とも折返し前後を同一IDで連続追跡できた結果ではない。

途中で見られた「1人に対して同時に複数候補」の出力は、今回の共通廊下ゲート内では0フレームだった。全領域のモデル出力はPedestrian 175、Car 195、Cyclist 1件。廊下ゲート外を網羅的に人手注釈していないため、これらから誤検出率を作っていない。

## 歩行経路の自然さ

実映像の代表15時刻と重畳画像を目視した。PointPillarsの近中距離のボックスは対象人物付近を通り、往路で奥へ、復路で手前へ移動する。主な進行方向は現行候補と一致する。8秒・24秒の代表画像でも、両方式の水平位置は人物のいる領域に対応する。骨格や足の動きは生成していない。

位置変動は、**両方式が同じ点群時刻で観測を持つ130標本**に限定して比較した。隣接観測間隔0.25秒以下の5観測窓だけで局所直線への残差を計算し、同じ116窓を使った。位置の平滑化や欠測補間は加えていない。

| 共通標本上の指標 | 現行の本人対応候補 | PointPillars |
| --- | ---: | ---: |
| 局所直線への平面残差・中央値 | **1.88 cm** | 3.19 cm |
| 同残差・90百分位 | **4.06 cm** | 6.86 cm |
| 隣接実観測からの速度・中央値 | 1.25 m/s | 1.27 m/s |
| 同速度・90百分位 | 1.60 m/s | 2.10 m/s |

今回の直線歩行では、PointPillarsが余計な横揺れや速度変動を減らす改善は見られなかった。単に滑らかであることを真の歩き方と同一視はしないが、遠方欠測も含め、**往復全体の経路を映像と照合する用途では現行候補を残すほうが有利**と判断する。

共通130標本での両方式の水平位置差は中央値5.13 cm、90百分位10.15 cm。横位置差の絶対値は中央値2.43 cm、90百分位7.79 cm。これは同じ点群から推定した異なる身体代表点同士の差であり、独立真値に対する誤差ではない。上の1.88 cm・3.19 cmも内部的な揺れであり、身体中心の絶対精度を保証しない。

PointPillarsの3Dボックスは、映像上で人物のおおよその領域に重なる一方、下端が床下へ出る例がある。主条件157出力のボックス下端は既存の水平化床に対して中央値約−0.369 m。このボックスから足の接地点や歩幅を測ることはできない。箱の中心と現行の可視点群中央値は高さも測定対象も異なるため、画像上で十字の高さが違うだけで人物誤対応とは判定しない。

## 入力条件への依存と限界

床上1.73 mの仮想原点を、設置校正のセンサー高さに対応する2.05065 mへ変える感度確認を、10点群おきの32フレームで行った。同じ広い比較区間に入る28フレームでは、人物出力が**主条件16フレームから別条件10フレームへ変化**した。別条件の間引き後の現行追跡は比較に使っていない。

モデルは高さの入力前処理に依存しており、そのまま移設や設置高さの変更へ頑健とは判断できない。Livoxの走査・点密度・取り付け視点・反射強度と、KITTIの車載LiDARのデータ分布の違いが影響する可能性がある。今回の結果だけでは、個々の原因を分離できない。主条件は全処理前に固定し、この結果から良く見える高さを選び直していない。

本比較は1人・1録画であり、実2人の遮蔽・追越し・ID入替、条件による回避差は未評価。位置・関節の独立真値もない。「学習済みモデル全般が現行方式より劣る」という一般化はしない。今回試した屋外データ由来PointPillarsの無追加学習での適用結果である。

## 今後の使い方

1. **現行の点群位置と未確定候補を保持し、確定・再捕捉を改善する。** 今回のモデルへ丸ごと置換する理由は得られなかった。モデルが復路で人物を支持した区間は、移動確認だけに依存しない確定処理を検討する材料になる。
2. **学習済み人物検出は存在確認・クラスタ分割の追加証拠として比較する。** モデル出力をそのまま高精度の位置や姿勢にせず、実点群の支持、画像対応、分離可能性を併記する。側寄せや減速の開始を消してしまう強い平滑化で自然に見せない。
3. **次の優先評価は実2人の追越し。** run_order.jsonの条件と実行動作を別々に注釈し、合体クラスタ、ID維持、条件別の欠測、横変位・減速量を検証する。導入・調整用と最終評価用は被験者・録画を分ける。
4. **遠方を主要測定にするならLivox・屋内条件への適応を検討する。** 代表的な人手ラベルと独立参照を用意し、別録画で評価する。欠測区間を時間積算で埋める場合も、人体の移動によるにじみと動作開始時刻の偏りを評価する。
5. **足・関節の自然さが目的なら別の検証が必要。** 人物検出モデルのボックスから関節を作らず、LiDAR人体姿勢推定等を独立の関節・足接地参照で評価する。

## 動作確認と再現

- 3フレームの読取り・推論・保存確認後、全318フレームを完了。`full/manifest.json`の`completed=true`、入力・コード・重みのハッシュを保存。
- CPUボクセル化の入力境界、柱あたり点数上限、先着点の保持、座標順序を小さな既知入力で確認。
- 公開実装のKITTIサンプル`000134.bin`を正の実行対照として推論し、Pedestrianの最大score約0.790を確認。これはモデルが動く確認であり、KITTIベンチマークの精度再現ではない。入力と結果は`kitti_control_result.json`を参照。
- 現行CSVは既存結果とバイト単位で一致。
- Chromeで比較画面の画像読込み・時刻スライダー・次の時刻・再生時間の進行を確認し、JavaScript例外0件。`comparison_v2/browser_verification.json`に保存。
- CPU4スレッドで、モデル推論部分の中央値約0.881秒/点群。全処理は約338秒の単発実行で、10 Hzの実時間処理ではない。高精度化・高速化の一般保証には使わない。

既存の録画003用校正は同一設置を前提とし、別録画へ無条件に適用しない。再現時は既存成果物を上書きせず、新しい出力先へ保存する。

```bash
source /opt/ros/jazzy/setup.bash
.venv_lidar_models/bin/python scripts/compare_pretrained_lidar.py \
  --bag /data/experiment_data/recordings/20261021_group002/recording_003/lidar \
  --config reports/20261022_pretrained_lidar_comparison/analysis_config.json \
  --output-dir reports/<新しい専用フォルダー>
```

専用環境を新規作成する場合は、`python3 -m venv --system-site-packages .venv_lidar_models`、続けて同じ環境の`python -m pip`で`torch==2.8.0+cpu`をPyTorch CPU用indexから、`torch-pointcloud==0.0.18`を通常indexから導入する。描画・ブラウザー確認の依存は`environment_freeze.txt`を参照。既存の録画用環境へ一括導入しない。

`analyze.py`は本録画用で、`full/`と感度確認用フォルダーから集計・表示を作る。`--output-dir`で新規フォルダーを指定できる。初回`comparison/`も保持し、共通時刻の追加集計を含む`comparison_v2/`を最新とする。
