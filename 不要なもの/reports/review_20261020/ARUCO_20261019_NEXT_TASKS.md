## 方針とタスク

今回の主目的が「LiDARで廊下座標のxy位置・速度を測る」「ZEDで姿勢を推定する」で、それぞれ独立に使うことなら、LiDAR–ZED間の6自由度外部校正は必須ではない。LiDARの廊下座標系とカメラ姿勢の解析は個別に進められる。両センサー間で同じ人物を自動対応させる、LiDAR位置を画像へ投影する、カメラ姿勢をLiDARの廊下位置に幾何的に結び付ける場合に、相対外部校正が必要になる。行動の時系列を比較するだけなら、時刻同期と人物ID対応は必要だが、相対6自由度変換は必須ではない。

### A. 今回の目的に必須: 各センサー内での位置・姿勢と精度検証

1. **LiDAR→廊下座標を設置ごとに確認する。** 床法線、廊下長軸・横軸に加えて、原点を共通にする測量済みランドマークを決める。LiDARとカメラを再設置したときは廊下フレームを更新する。
2. **LiDAR位置の意味と正解を定義する。** 現行トラック位置は点群クラスタの代表点であり、必ずしも床上の人体中心ではない。どの身体位置を軌跡と呼ぶか決め、既知の床位置、上方映像または測量参照と比べ、距離・人数・遮蔽別の誤差を測る。
3. **カメラの人物姿勢を解析する。** 実際の歩行試行にWindows用 `analyze_svo_body_tracking.py` を実行してBODY_34を出力し、姿勢の欠測・ID継続・遠距離画質を確認する。SDKの関節位置は解剖学的な真値ではないため、必要な精度を独立ラベル/参照で確かめる。
4. **姿勢と軌跡の反応を同じ時刻で比較するなら同期する。** ZEDとROSの時計差・driftを共通イベントまたは時計同期記録で確認し、人物のID/役割を映像注釈と対応させる。LiDAR内の速度だけを求める場合、ZEDとの同期は不要。

### B. 条件付き: LiDAR–ZEDの6自由度校正

LiDAR軌跡とカメラ骨格を自動的に空間対応させる場合だけ、以下を実施する。

1. **既存ドア凹部での試行（完了、候補は棄却）。** [10/13録画のドア校正試行レポート](../door_calibration_20261013/README.md)のとおり、静的な空廊下を前後半に分け、前半の左右ドア領域だけで点群ICPを行い、後半40 LiDARフレーム・8 ZEDフレームで検証した。候補は現行変換から6.69°・48.6 cm変化し、左手前ドアは改善したが右凹部と全体は悪化したため不採用。候補は適用していない。今回のレビューには既に画像・深度があり、追加のZED SDK書き出しは不要だった。
2. **必要ならドアの共通特徴を手動対応する。** 自動ICPでは左右扉の一貫した整合が得られなかった。次の既存データ解析では、複数ドアの固有な枠角・凹部側面について、画像座標とZED深度、LiDAR XYZを直接対応付け、扉番号を記録する。十分な対応点が点群に存在しなければ自動校正を続けず、既知ターゲットを使う。
3. **候補を未使用のドアで検証する。** 共通特徴から候補を作れた場合に限り、最適化に使わなかったドアの投影ずれ・平面残差で確認する。似た扉の誤対応をドア番号や廊下内の順序で防ぐ。LiDAR点密度で縁・奥面の点が不足するなら次の板方式へ進む。
4. **現物ターゲットを使う場合は寸法を確定する。** ArUco辺長、マーカー中心と板中心のずれ、板の幅・高さ・剛性・平面性を記録する。今回の画像では150 mm四方のマーカーのみが確認でき、250×180 mm板のLiDAR観測を前提にできない。
5. **LiDARが面として観測できる板を用意する。** 剛体・平面・拡散反射面を持つ板に既知マーカーを固定し、板全体をLiDARから見える状態にする。床・壁に重ならないように保持する。
6. **必要な場合だけ新しい校正録画を取得する。** 板をセンサーから約1–3 mに置き、6姿勢以上（できれば10姿勢以上）で、板法線が3次元に広がるよう傾ける。各姿勢を約1秒静止させ、ZED画像・ZED IMU・`/livox/lidar`・`/livox/imu`を同時に記録する。画面上の板境界とLiDAR点の面内2方向の広がりを確認する。
7. **時刻offsetを独立に測る。** 動く板で対応時刻を取る場合は、移動開始/停止などの共通イベントを複数回記録する。LiDAR 10 Hzの標本化と検出幅を含む不確かさ、必要ならdriftを報告する。静的なドア校正では、記録開始時刻差をoffsetとして入れない。
8. **廊下の絶対座標を別に固定する。** 例えば入口側の特定ドア枠角を原点、廊下長手をX、横手をYと定義し、他のドア位置を巻尺/測量で記録する。ドア点群への位置合わせだけでもローカルな軸は作れるが、既知原点と寸法がなければ試行間で共通の絶対位置にはならない。
9. **候補変換を未使用特徴で検証する。** 面点数・エッジ位置・残差・条件数・leave-one-out変化を確認し、最適化に使わなかったドアでも投影を検証する。独立検証を通るまで `--apply` は使わない。

offsetが実測できた後の実行形は次のとおり。最初に実測値を入力し、空文字や未検証の仮値を渡さない。

```bash
read -r -p 'Verified offset seconds (LiDAR = ZED + offset): ' verified_lidar_minus_zed_seconds
: "${verified_lidar_minus_zed_seconds:?offsetを設定してください}"
[[ "$verified_lidar_minus_zed_seconds" =~ ^[+-]?([0-9]+([.][0-9]*)?|[.][0-9]+)([eE][+-]?[0-9]+)?$ ]] || { echo 'offsetは数値で入力してください' >&2; exit 2; }
python3 scripts/calibrate_zed_lidar_aruco.py \
  --review-dir /data/experiment_data/<新しい校正レビュー出力> \
  --bag /data/experiment_data/recordings/<新しい校正録画>/lidar \
  --output-dir reports/aruco_calibration_<新規名> \
  --lidar-time-offset-seconds "$verified_lidar_minus_zed_seconds" \
  --max-observations 20
```

校正出力先は新しい空の名前を使う。レビュー・bag・出力パスの山括弧部分は新しい録画の実パスへ置き換える。

### C. ZED SDKで追加解析するもの

- **今回のArUco平面校正には追加のSDK解析は不要。** 画像・内部パラメーター・IMUの書き出しは完了している。Body Trackingを実行しても、今回の小ターゲットにLiDAR面点が足りない問題や時刻offsetは解決しない。
- **カメラ姿勢の精度確認。** 10/13の1人往復録画はBODY_34を書き出し済み。人物ID・検出confidenceは安定した一方、足首confidenceが低く、歩容周期の評価には不足した（[LiDAR/ZED独立評価](../independent_walk_20261013/README.md)）。2人追越しでカメラ側が両者を検出・追跡できるかは未評価なので、Windows用 `analyze_svo_body_tracking.py` を2026-10-19の`recording_001`と`recording_003`に実行し、映像で実際の行動を確認する。可能なら同一SVOをSDK 5.5以降のBODY_34 GEN_2でも再解析してSDK 5.4出力と比較する。SVO2はローカルから読み、出力は共有領域の新規フォルダーへ保存する。
- SDKの人物ID/骨格は推定値であり正解ラベルではない。人物ごとの存在区間・役割・ID対応は映像で注釈し、位置誤差を評価するには床面基準点の独立測量または第三視点の参照軌跡も用意する。
