# 校正変換から独立した1人歩行の確認

## 結果

LiDAR単体の確認では、確定トラックID 44 は廊下方向へ進んで折り返し、戻る軌跡を保っています。位置の往復は自然な歩行と矛盾しません。水平速度の中央値は **1.16 m/s**、p90は **1.63 m/s**、使った連続検出間隔は最大250 msに制限しました。折返し前後で廊下方向の増減がそれぞれ98.9%・98.8%同じ向きを保ち、0.25秒を超える欠測は2回（最大0.301秒）です。

ただし、この記録は1人が廊下を往復する試験です。LiDARの確定点は171点、XY移動距離は22.84 m、始点と終点の差は0.82 mでした。横方向の範囲は-0.39〜0.23 mです。クラスタ代表点の高さは0.25〜1.27 mと変動するため、LiDARのZやクラスタ中心を解剖学的な身体中心とはみなせません。短い速度ピークを含み、独立な正解軌跡もないので、ここで言えるのは動線の見た目が妥当という範囲です。

この解析は [LiDAR追跡CSV](/home/hp-ubuntu/experiment_recorder/reports/review_20261020/final/tracks.csv) の `corridor_x/y/z` と検出点だけを使っています。`lidar_to_zed_left_eye.json` によるLiDAR→ZED変換も、ZEDとの融合結果も計算に使っていません。廊下座標はLiDAR単独の重力・壁面校正に依存します。

## ZED人物検出と関節推定

ZED SDK出力は**人物検出・ID追跡そのものは安定**しています。この単独歩行の可視区間で817件が`OK`、IDは0のみ、人物検出confidenceの中央値は91.6/100でした。BODY_34のSDK書き出しはSDK 5.4の`HUMAN_BODY_ACCURATE`、body fitting=True、segmentation=True、深度`NEURAL`で行われています。

問題は人物の有無より**脚・足首の関節推定**にあります。全距離での関節confidence中央値は膝が左右75.2〜77.2、足首が左右54.0〜59.0です。カメラ深度9 m以上では足首confidence中央値が左33.4、右35.5まで低下します。前段の融合歩容レポートで左右の足首角がそれぞれ約129.806°にほぼ固定されていた点も、歩行周期を測るには足元の骨格出力が不足していることと整合します。

映像上でも近距離では足元が画面下端にかかり、書き出された足先キーポイントが画像範囲外へ出るフレームがあります。一方、遠距離では全身が画面内に入っても足首のconfidenceが低くなります。画面に写っていない足位置はSDKの別設定だけでは回復できません。

したがって、今回確認した範囲では**廊下上の大まかな歩行軌跡はLiDAR側で妥当に見え、歩容の自然さを評価できない主因はZEDの人物検出ではなく足元の姿勢推定精度**です。とはいえ2人追越し時のID維持は未評価です。

## SDKで改善できる範囲

現在のデータは既に`HUMAN_BODY_ACCURATE`と`BODY_34`、fitting、segmentationを使っています。これはSDKの精度優先の検出モデルです。現在のSDK 5.4世代から設定を少し変えるだけで人物検出が大きく改善するとは期待しにくく、信頼度しきい値を下げても低確度の足首点を拾いやすくなる代わりに誤点も増えます。

既存SVO2をSDK 5.5以降で再解析すれば、GEN_2モデルを比較できます。StereolabsはGEN_2について、混雑・通常と異なる身体向きへの頑健性向上と精度改善を説明しています。ただし今回の単独歩行での足首精度や歩容評価に対する改善保証ではありません。既存の記録でSDK 5.4/5.5のBODY_34出力を並べ、低確度関節の数・連続性・動画上の明らかなずれを比較する価値はあります。体幹・腕の姿勢や2人の人物IDには改善可能性がありますが、身体マーカーの代わりになるほどの足関節計測を保証するものではありません。BODY_38も足・手の追加キーポイントを持つため比較候補ですが、形式を変えるだけで実画像で見えない足接地が得られるとは限りません。

足接地や歩行周期を定量評価するなら、側面からの高解像度撮影で足元が十分な画素数を持つようにするか、マーカー式モーションキャプチャなど独立参照を追加してください。SDKの`minimum_keypoints_threshold`や`skeleton_smoothing`は低品質スケルトンの除外・時間平滑には使えますが、見えていない足位置の真値を復元する機能ではありません。
