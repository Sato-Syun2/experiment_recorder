# 録画003：3〜15 m往復の測定状況と上面表示

対象: `20261021_group002_recording_003_walk_review`。ユーザーの用途は「大まかな歩行経路の確認」。保存済みファイルだけを解析し、ZED・Livox・ROSノード・RViz等の実機操作は行っていない。ユニットテストは実行していない。

## 判定

**映像と未確定候補を併用すれば、廊下中央を約15 mまで進み、折り返して戻る大まかな経路を確認できる。確定検出だけで連続した自動測定を行うには不十分。**

- 候補を含む観測位置は、最大X **15.018 m**。確定実検出は往路で最大 **14.844 m**。
- 往路ID 17と復路ID 60の映像投影を照合し、同じ1人の往復に対応すると判断した。自動IDは折返し付近で分かれている。候補を確定に昇格したり、CSVを書き換えたりしていない。
- 3〜14 mで、0.25秒以下の隣接観測は、往路で奥行きが増え、復路で減る。各方向の一致率は100%。往復の経路形状は自然。
- 横位置は候補を含め **−0.102〜+0.232 m**。同じ1 m距離帯で往路・復路の横位置中央値を比較すると、差の中央値 **8.1 cm**、最大 **17.4 cm**。中央付近の往復として整合する。ただし、実際に往路と復路で歩く線が異なる可能性があり、これを測位誤差と解釈しない。
- 5観測の局所直線からの平面残差は、中央値 **2.1 cm**、90百分位 **5.1 cm**（150標本、観測間隔0.25秒以下の窓だけ）。これは短時間の内部的な滑らかさであり、身体中心の絶対位置精度・95%誤差範囲ではない。欠測の多い遠距離全体を代表しない。

位置が15 m付近まで達すること、横方向に大きな飛びがないこと、往復の向きが一致することから、**この1人・直線往復の録画を目視確認する用途には使える**。候補の照合なしに自動集計する用途、複数人のID維持、10 cm等の絶対精度は、この結果では保証できない。

## 表示の開き方

[上面図・映像・経路の再生](index.html) をブラウザーで開く。サーバー・ネット接続・ZED SDKは不要。

- 初期表示は映像の約10秒。全経路を表示する。
- 再生、時刻スライダー、距離対時間グラフのクリックで時刻を選択できる。
- 上面図のXは廊下の奥行き、Yは中央からの横位置。単位m、縦横は同じ縮尺。センサー側を左、奥を右に表示する。
- 濃青は `status=confirmed` かつ `detected=1`。橙は未確定候補の実観測。予測は初期状態では非表示で、選択時は灰色の空円で表示する。
- 未確定候補を非表示にすると、確定実検出だけでは復路の大部分が欠けることを確認できる。
- ID間、観測間隔0.25秒超は経路線で接続しない。長い欠測を補間で隠していない。
- 映像の橙枠は画像前景候補。LiDAR中心の投影は青または紫の十字。意味的な人物認識・骨格推定ではない。

HTMLと `review_frames/` を同じフォルダーに保つ。[静止軌跡図](trajectory.png) と [映像・投影の代表21画像](correspondence_review.jpg) も参照できる。

## 検出継続性

LiDARは318フレーム、ZEDレビューは300画像・深度組（約29.968秒）。画像・深度は全300組の読込と寸法を確認した。追跡処理の完了をメタデータで確認した。

映像上で人物を確認するための広めの区間 **ZED経過2.0〜29.8秒** を分母とする。この区間は独立に測量した3〜15 mの位置ゲートではなく、近距離の進入・退出と前後の短い空の余白も含む。以下の割合は確認区間内のフレームカバー率であり、厳密な人物存在ラベルに対する再現率や、正確な3〜15 m滞在時間に対する検出率とは区別する。

|項目|結果|
|---|---:|
|区間内の処理LiDARフレーム|278|
|確定実検出|93 / 278（33.5%）|
|選定した候補IDを含む実観測|185 / 278（66.5%）|
|確定観測間の最大間隔|11.399秒|
|候補も含む観測間の最大間隔|0.699秒|

**66.5%を人物の確定検出率には数えない。** 分母は検出ゼロを含む `tracks.frames.csv` を使い、追跡CSVの行数では数えていない。

確定観測の大きな途切れは、ZED基準時刻 **14.248〜25.646秒**。往路のID 17が終わり、復路のID 60が約4.05 mまで戻ってから確定する。候補も含めると経路は残るが、13 m以遠では0.3〜0.4秒程度の間隔もあり、折返しのID切替では約0.7秒空く。予測で15 mを超えて進み続ける点があっても、到達位置の実検出に使わない。

13 m以遠の観測クラスタ点数は、往路・復路とも中央値10点。確認用の [確定条件の診断CSV](confirmation_diagnostic.csv) では、復路の遠距離で短い欠測のたびに連続観測窓がリセットされ、15観測の移動整合性判定を満たしにくい。8 m未満では平均点数の確定条件も20点に上がる。復路は観測候補があっても長く未確定のままで、25.646秒に確定する。確定処理の緩和は本解析では行っていない。

[距離帯別の観測数](metrics.json) は、未検出時の真の位置がないため距離別検出率とは扱わない。

## 座標・校正と精度の限界

録画002から推定済みの床面・壁軸と、3、5、7、9、11、13、15 mのポール公称位置を使った原点候補を、歩行解析前に固定した。歩行軌跡に合わせて調整していない。距離のスケール補正も行っていない。

- 解析専用: `analysis_config.json`、`corridor_candidate.json`。ルート `config.json` や運用中の `tracking/*.json` は変更していない。
- 原点は、ポール推定位置と申告距離の差の中央値（−0.10418 m）で合わせた。ポール7配置の残差は最大絶対値4.94 cmだが、原点を合わせた同じ校正データ上の残差であり、独立検証の誤差ではない。
- 録画002→003のIMU上方向の差はLiDAR約0.013°、ZED約0.027°。大きな姿勢変化は見られないが、並進移動や完全な同一設置はこれだけでは証明できない。床高さ・壁・原点候補の流用は同じ設置を条件とする。
- 人物位置はLiDARクラスタ観測点の中央値。解剖学的な身体中心、足の接地点ではなく、前後の向きや見えている身体表面でも変わる。
- 「3〜15 mを往復」という申告だけから、身体中心の各時刻の正解位置は作っていない。独立真値がないため、絶対位置のMAE・RMSE・±何cmという保証値は出していない。

## ZED深度との比較

冒頭12画像の背景と各画像の差から前景領域を抽出し、領域内側の深度中央値を求めた。選択にLiDARの予測位置を使っていない。反射や背景の混入、領域の身体部位の違いがあり、意味的な人物検出ではない。

録画003の生の絶対タイムスタンプで近傍の点群を選んだ。時計差の推定・補正は未確定。先頭画像と点群の開始差約1.853秒を時計offsetとして補正していない。点群ヘッダーは走査区間の代表時刻でもあり、近傍時刻だけで動体の同期精度を保証できない。

185組のZED前景深度とLiDAR投影深度の差は、符号付き中央値 **−0.273 m**、差の絶対値の中央値 **0.278 m**、90百分位 **0.826 m**。時計の対応先を±0.2秒変える感度確認でも、絶対差中央値は約0.21〜0.40 m。この値が小さくなるずれを正しい時計補正と決めていない。

この比較は別の身体表面の代表点、校正候補、深度の揺れ、未確定の時計差を含むため、ZEDまたはLiDARの真の測位誤差ではない。**2つのセンサーが数cm精度で一致することは確認できていない。** 大まかな経路の確認にはLiDAR平面軌跡と映像を主に使い、深度平均や融合によって精度が上がったとは扱わない。

## ファイルと再現

入力原本は共有領域の `20261021_group002_recording_003_walk_review/` と `recordings/20261021_group002/recording_003/lidar/`。原本・既存の録画メタデータは変更していない。録画002校正候補の入力は隣の `../20261021_group002_pole_calibration/` にある。

- `tracks.csv`、`tracks.frames.csv`、`tracks.metadata.json`: 元の状態を保持した追跡結果。
- `metrics.json`、`path_consistency.json`: 検出継続性・経路の内部整合性。
- `image_measurements.csv`、`clock_sensitivity.json`: 前景深度比較と時刻対応の感度。
- `manifest.json`: 小さな入力・処理コードのSHA-256、実行環境。
- `assess.py`、`path_consistency.py`、`dashboard_template.html`: 解析・可視化コード。既存出力があると停止する。

追跡の実行コマンド:

```bash
source /opt/ros/jazzy/setup.bash
.venv/bin/python scripts/track_people.py \
  /data/experiment_data/recordings/20261021_group002/recording_003/lidar \
  --config reports/20261021_group002_recording_003_walk_assessment/analysis_config.json \
  --output <新しい専用フォルダー>/tracks.csv
```

解析コードはこの専用フォルダー内の入力・出力を使う。再解析する場合は新しい専用フォルダーへコードと解析設定を準備し、`assess.py`、次に `path_consistency.py` を実行する。校正ファイルは記録003解析用に固定したものを使用する。共有原本をコピーする必要はない。
