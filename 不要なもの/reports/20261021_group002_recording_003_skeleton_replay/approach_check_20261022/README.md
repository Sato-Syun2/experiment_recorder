# 本番の接近動作を模したSDK新規追跡の比較

## 状態

**2026-10-22に外部SDK PCで2条件を実行済み。** 約15 m・13 mの両方で、復路だけを新規SDK起動して再推定した。数値と判定の範囲は [実行結果](RESULT_20261022.md)、旧・新SDK比較ページは実行フォルダーの `reviewed_20261022/index.html` を参照。ZED SDK単体とLiDAR経路を比較した接近専用ページは [比較結果](ZED_LIDAR_COMPARISON_20261022.md) と共有実行フォルダー内の `zed_lidar_comparison_20261022/index.html` を参照。

本番は奥から近づく動作だけというユーザー申告に合わせ、録画003の復路から新規にSDKを起動する。以前のCSVを切り出すだけでは、往路で生じた追跡状態を引き継いだ結果のままなので、SVO2の該当フレームから骨格を推定し直す。 再生画面は再生バー上部の「3D視点」メニューから上面図を選べる。比較ページからは「上面図で再生」を押すとその視点で開く。
## 実行結果

15 m条件は285フレーム全てを処理し、282フレームで骨格を検出した。固定した同一人物の骨長スクリーニングを278フレーム（97.5%）が通過し、両脚の関節confidenceが25以上だったのは214フレーム（75.1%）。開始直後4観測だけが骨長基準を外れた。

13 m条件は240フレーム全てを処理し、237フレームで骨格を検出した。検出した237フレーム全てが骨長スクリーニングを通過し、両脚の関節confidenceが25以上だったのは203フレーム（84.6%）。

以前の往復全体処理は同じ時刻範囲で両条件とも形状整合0フレームだった。今回の録画の接近区間では、新規起動で骨格の形状崩れを避け、概略経路を再生できることを確認した。これは位置・関節の正確さ、本番全条件、空の廊下から人物が進入する検出を保証しない。

## 固定した条件

|条件|原録画の時間|SVO元フレーム範囲|期待枚数|開始付近の既存LiDAR候補X|
|---|---|---|---:|---:|
|約15 mから新規追跡|17.0〜26.5秒|508〜792|285|14.777 m|
|約13 mから新規追跡|18.5〜26.5秒|553〜792|240|13.108 m|

17秒付近の画像で人物が手前を向いていることを確認した。終点26.5秒は約3 mまでの接近を確認するための時間窓。距離は既存の未確定LiDAR候補も含む参考位置で、独立に測量した3〜15 mの厳密な位置ゲートではない。試行計画や元の録画メタデータは変更しない。

SDKはSVOを開いた直後、**grab・位置追跡・骨格追跡の開始前に**対象フレームへシークする。往路・折返しのフレームに対してBody Trackingを走らせない。各取得時刻を以前のSVO書き出しの全フレーム時刻と照合し、一致しなければ停止する。フレーム番号×fpsで時刻を作らず、元の画像絶対時刻と録画冒頭からの経過時刻を保つ。

BODY_34、HUMAN_BODY_ACCURATE、body fitting / tracking / segmentation有効、深度NEURAL、最大30 m、confidence35は以前と同じ。今回変更するのは解析開始区間とSDKの初期状態。校正JSON・骨格の尺度・姿勢・時計offsetは変更しない。

## 比較するもの

同じ画像タイムスタンプの以前の往復全体の結果と、新規追跡結果を比較する。以前の結果では、両窓とも形状整合かつSDK OKのフレームは0件（基準は下記）。これは新しい処理が失敗することを意味せず、改善前の比較値。

- SDK OKのフレーム数と割合。
- 形状チェックを通過したSDK OKのフレーム数と割合。
- 左右の股・膝・足首のconfidenceがすべて25以上であるフレーム数。
- 最初の形状整合までの時間、形状整合の最大欠落時間、ID数。
- 胴体、大腿、下腿の長さの範囲と中央値。
- 実画像への骨格の重なり、3Dの床・頭・足の位置関係。

形状チェックの基準は、**以前の往路4.5〜10.5秒の同じ人物から求めた骨長**を固定使用し、今回の結果から基準を作り直さない。基準の0.5〜1.8倍を外れる骨格を不整合とする。これは検証補助で、人体寸法の真値・測位誤差・関節角の精度ではない。confidenceやSDK OKだけで正常と判断しない。

SDK出力が揃っても、統計だけで本番使用可能と断定しない。再生画面で人物に対応しているか確認する。骨格が新規追跡で安定すれば、「今回の録画の接近区間では履歴を引き継がない条件で改善した」と判断できるが、SDK内部の原因や本番全条件の精度保証にはならない。

## 本番との違いと制限

- 本番の「空の廊下で待機していて、奥から人物が入る」場面そのものではない。今回は遠方に既に人物が写っている時点でSDKを新規起動する。
- 深度・位置追跡も新規初期化するため、Body Trackingの履歴だけを単独に操作した原因実験ではない。
- 今回の新規追跡はZED骨格。LiDARは以前の観測を参照表示するだけで、新規追跡をやり直していない。未確定候補は確定人物検出に数えない。
- 1人・1録画の再解析。複数人・遮蔽・別の設置は未評価。独立真値がないため位置RMSEや関節精度は算出しない。
- SDK対応PCのローカルSVO2を読む。共有経由のSVO指定は拒否し、大容量録画を複製しない。カメラ・LiDAR実機、ROS、RVizは起動しない。
