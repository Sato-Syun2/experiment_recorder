## 骨格が崩れる区間

SDKがOKとした観測に対し、以下の記録固有の形状チェックを行った。

1. 同じ人物の往路4.5〜10.5秒における、骨盤→首、左右の大腿、左右の下腿の長さの中央値を基準にする。
2. いずれかが基準の0.5倍未満または1.8倍超なら、形状不整合として表示上区別する。
3. 原CSVや関節座標は補正しない。この閾値は目視確認の補助であり、人体寸法の真値でも精度合格基準でもない。

|SDK OKの内訳|件数|時刻範囲|
|---|---:|---|
|形状チェック通過|365|2.367〜14.534秒|
|形状不整合|392|15.867〜28.901秒|

往路の下腿基準は約0.308 m、大腿は約0.347 m、骨盤→首は約0.525 m。復路の多くでは、下腿が約1.244 m、大腿が約1.399 mへ伸び、胴体が約0.18 mへ縮む。左足首が床から約3.6〜3.8 mの高さに出る。足が頭より高くなる形状は、実際の歩行映像と一致しない。

これらは**座標変換や新しい再生画面が作った崩れではない**。

- SDKが書き出した元の2D確認画像にも、復路で人物から上方へ伸びる骨格がある。
- 剛体変換前の3D関節でも、下腿長が約1.24 mになっている。
- SDKの局所関節位置 `local_position_per_joint_json` にも同じ下腿・大腿の長さが記録されている。
- 関節の3D点を内部パラメーターで投影した結果は、書き出された2D点と整合する。2Dと3Dの整合だけでは、映像上の正しい身体位置であるとは言えない。

原因がSDK内部の追跡・body fitting・推論のどの段階かは、本出力だけでは確定できない。モデルや関節の並べ替えで見た目を直す処理はしていない。

## 信頼度の扱い

形状不整合392件でも人物confidenceの中央値は **88.7/100**、最大100。SDKのOK状態やconfidenceだけでは、骨格が正しいと判断できない。

SDK OK全体の関節confidence中央値は、左膝69.1、右膝71.3、左足首48.7、右足首48.5。関節confidenceを25以上に制限するだけでは、復路の誤った骨格を除外できない。そのため、関節信頼度と形状チェックを別に表示する。

近距離の進入・退出では足元が画像外へ出る。遠距離・折返し付近にはSEARCHINGも含まれる。非表示になった関節や骨格を、人体モデル・前フレームの保持・補間で埋めていない。

## 位置と精度の範囲

骨格はZED IMAGE座標[m]から、固定した録画002由来の外部変換・床水平化・廊下座標候補で変換する。廊下原点、尺度、向きは歩行データに合わせて調整していない。LiDARへ骨格を吸着させる処理も行っていない。

形状チェック通過観測の骨盤は廊下Xが最大約13.72 m。ただし骨盤・身体表面・LiDARクラスタ中央値は異なる点であり、身体の真の到達位置の計測値とは同一視しない。大まかな経路の評価では、既存のLiDAR候補が約15.02 mまで達することと実映像の往復を使う。

形状チェック通過のZED骨盤と、時刻差60 ms以内で対応したLiDAR観測候補277組では、X差の中央値は−0.278 m、Y差は+0.003 m。時計差は未推定で、身体の基準点も異なるため、この差は位置誤差・センサー精度の検証値ではない。

独立した関節・位置真値はなく、絶対誤差MAE/RMSEや±何cmという保証値は出していない。前のLiDAR確認で得た局所的な揺れ約2 cmも、骨格の位置精度を意味しない。

新しい再生HTMLと解析結果は、この `verified_20261022/` と、共有側の同名フォルダーへ保存する。既存の外部PC出力は保持する。HTMLの親フォルダーにある `assets/` との位置関係を保つ。
